# BOAT RACE AI Cloud v5

スマホ向けの競艇予想・バックテスト・自己改善Webアプリです。

## V5で増えた機能

- 過去レースを期間・場・件数で指定して一括取得
- 過去レースを時系列順に再生するウォークフォワード検証
- 予想時点より未来の結果を学習に混ぜない設計
- 各レースごとにSupabaseへチェックポイント保存
- Streamlit画面を閉じても続きから再開
- GitHub Actionsワーカーによる未処理ジョブの自動継続
- 予測→結果照合→候補モデル再学習→旧基準モデルとの比較→改善時だけ採用
- Log Loss / Brier Score / 券種・評価分類別の参考回収率
- 解析モデル + Monte Carlo仮想レース
- 単勝 / 複勝 / 2連単 / 2連複 / 拡連複 / 3連単 / 3連複
- 市場×AI評価
  - 両者一致・手堅さ
  - AI優位・過小評価
  - 市場優位・AI慎重
  - 双方低評価・見送り
- スマホ向けカードUI

## V5.1 追加: 要素重みスライダー

予想画面の「🎚️ 要素の重みづけ」で次を0〜200%に変更できます。

- コース/進入
- 級別
- 全国成績
- 当地成績
- モーター
- ボート
- 平均ST
- 展示タイム
- 展示ST
- F/Lペナルティ

100%が標準、0%で無視、200%で標準の2倍です。

プリセット:

- 標準
- ST重視
- 機力重視
- 選手実力重視
- 当地・水面重視
- 展示重視

自己学習モデルが採用済みの場合は、「自己学習モデルがある場合の手動重み反映度」で、学習モデルと手動重みモデルを混合できます。

一括学習ジョブには、作成時の重みを固定保存します。したがって「標準500R」と「ST重視500R」のように条件を固定して比較できます。

## 自動一括学習の考え方

例:

1. 2026-06-01〜2026-08-31、最大1000Rのジョブを作る
2. 開催日・開催場を確認してキューを作る
3. 古いレースから順に出走表・直前情報・オッズを取得
4. その時点より前に確定した履歴だけでモデルを構築
5. 解析確率 + Monte Carloを計算
6. 実際の結果・払戻を取得して照合
7. Supabaseへ保存
8. 次のレースへ
9. 履歴が増えると候補モデルを再評価
10. 新候補が検証用の新しいレースで基準モデルを改善した場合だけ採用

## ファイル

- `streamlit_app.py`: スマホ向けWeb UI
- `core.py`: 予測・Monte Carlo・券種確率・買い方評価・学習
- `backtest.py`: 過去一括学習エンジン
- `storage.py`: Supabase保存・キュー管理
- `worker.py`: GitHub Actions用自動処理ワーカー
- `supabase_schema.sql`: DBテーブル作成/移行SQL
- `.github/workflows/v5-backfill.yml`: 自動バックフィルWorkflow
- `requirements.txt`: Python依存関係
- `SETUP.md`: 詳細セットアップ

## 注意

- 自動投票は行いません。
- 確率・期待値・参考資金配分は利益を保証しません。
- 過去オッズは取得できる範囲で検証します。取得不可レースは予測精度学習には使えても、買い方ROI検証には使えない場合があります。
- `pyjpboatrace` は第三者OSSなので、取得先サイトの仕様変更で修正が必要になる可能性があります。
- 過去取得は短時間に大量アクセスしすぎないよう、ワーカーに待機時間を入れています。
